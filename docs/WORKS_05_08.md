## №5 Ссылки и цели якорей

`catalog.html` открывает другой документ. `#popular` выбирает элемент текущего документа. `index.html#popular` сначала открывает главную, затем указывает на элемент с id="popular".

Подвалы пяти страниц содержат одинаковые ссылки на advantages, popular и contacts главной. Идентификатор contacts назначен информационному блоку главной со ссылкой на контактную страницу: это не отдельная встроенная форма обратной связи.

CSS `.section:target, .info-banner:target` выделяет цель фрагмента URL. `outline` не меняет размеры блока; отрицательный outline-offset размещает рамку внутри. `scroll-margin-top` добавляет запас при прокрутке, но не постоянный отступ в раскладке. При переходе к разделу закреплённая шапка не должна закрывать его заголовок.

Ширина и масштаб браузера всё равно требуют проверки: если шапка выше заложенных 100px, запас нужно адаптировать. На узком экране шапка в существующем медиазапросе перестаёт прилипать; запас снижается до 24px. При запросе уменьшенного движения плавная прокрутка отключается.

## №6 Именованные области Grid

```css
.catalog-layout {
  display: grid;
  grid-template-columns: 240px minmax(0, 1fr);
  grid-template-areas: "filters products";
}

.catalog-filter {
  grid-area: filters;
}

.catalog-content {
  grid-area: products;
  min-width: 0;
}

@media (max-width: 900px) {
  .catalog-layout {
    grid-template-columns: 1fr;
    grid-template-areas: "filters" "products";
  }
}
```

Карта у родителя определяет две области, дочерние блоки выбирают их по имени. В широком варианте фильтр получает 240px, товары — оставшуюся ширину. minmax(0, 1fr) и min-width: 0 помогают содержимому сжиматься в доступном пространстве.

При ширине до 900px недостаточно изменить только число колонок: двухколоночная карта областей могла бы создать дополнительный трек. Поэтому карта тоже меняется на две строки. Сетка карточек и Flexbox внутри карточки остаются отдельными уровнями раскладки.

## №7 БЭМ и согласованность кода

| Компонент | Блок | Примеры элементов и модификаторов |
|---|---|---|
| Меню | site-nav | site-nav__list, site-nav__item, site-nav__link--active |
| Карточка | product-card | product-card__title, product-card__price, product-card__badge--sale |
| Крошки | breadcrumbs | breadcrumbs__link, breadcrumbs__current, breadcrumbs__separator |
| Форма | order-form | order-form__field, __label, __input, __select, __textarea, __actions; order-form--page |
| Окно | order-dialog | order-dialog__title, order-dialog__description, order-dialog__close |
| Сообщение | success-message | success-message--toast |
| Кнопка | button | button--secondary, button--wide |

Сокращения __label и другие в таблице означают полные имена с префиксом order-form. В настоящем HTML классы записаны полностью.

Например, `.order-form__input` оформляет поле независимо от количества промежуточных div. Идентификаторы order-name и page-name сохранены для label и JavaScript. Наличие id не противоречит БЭМ; нежелательно строить через него переиспользуемые стили.

Не у каждого служебного класса должна быть собственная CSS-декларация: product-card__button используется JS как точка поиска. button задаёт общий вид действия, product-card__action — раскладку внутри карточки. Это смешение ролей двух классов на одном элементе, а не два разных элемента.

Для детали товара убраны случайные элементы product-card вне карточки: product-detail__badge и product-detail__category имеют своё смысловое место и разделяют часть правил с карточкой.

## №8 Форма и модальное окно

Формы сохраняют ограничения HTML: required, minlength, type=email и точный pattern телефона. Внешне подходящий телефон без скобок не пройдёт текущий pattern: это известное ограничение учебного варианта, а не универсальная проверка номеров.

validateAndSubmit подключает события к форме. При submit он отменяет стандартную отправку через preventDefault, убирает старое сообщение, проверяет ограничения и отмечает ошибочные поля через aria-invalid. При неверных данных reportValidity показывает сообщение браузера, выполнение прекращается.

При корректных данных вызывается reset, затем показывается честное сообщение о демонстрации. fetch или другой сетевой отправки в коде нет. Имена полей name подготовлены для структурированного сбора данных, но сервер не подключён.

При input/change исчезает прежнее сообщение успеха; исправленное поле теряет aria-invalid. Кнопка «Очистить» вызывает нативный reset, который также сбрасывает отметки и сообщения. reset возвращает исходные значения HTML, а не обязательно пустые строки.

Для order.html?product=mouse скрипт ищет разрешённый option. Его defaultSelected становится true, чтобы после reset сохранялся товар из ссылки. Неизвестный идентификатор не подставляется: остаётся предложение выбрать товар.

Модальное окно открывается методом showModal и закрывается через close. Перед повторным открытием форма сбрасывается и устанавливается товар нажатой карточки. Нативный dialog отвечает за базовое модальное поведение; Escape должен проверяться в настоящем браузере.

Клик с target === dialog может приходиться на внутренний padding, поэтому дополнительно сравниваются координаты с getBoundingClientRect. Внутренний отступ больше не считается фоном снаружи. Это не отменяет проверки настоящим указателем и клавиатурой.

## Ответы для повторения

Вопросы сохранены в порядке четырёх приложенных файлов. Всего 74. Определение нужно дополнять примером из собственного проекта.

### Практическая №5

**1. Что такое многостраничный сайт?**

Сайт из нескольких HTML-документов, связанных ссылками. В ShopProject это главная, каталог, товар, заявка и контакты.

**2. Чем ссылка на HTML-страницу отличается от якорной ссылки?**

Ссылка catalog.html загружает другой документ. Якорь #popular указывает на элемент внутри текущего документа. index.html#popular совмещает оба действия.

**3. Для чего используется атрибут id?**

id задаёт уникальный идентификатор элемента внутри документа. Он нужен для якорей, связи label с полем и поиска в JavaScript; для общего оформления удобнее class.

**4. Как создать ссылку на раздел текущей страницы?**

Создать элемент с id="advantages" и ссылку href="#advantages". После перехода фрагмент адреса указывает на этот id.

**5. Как создать ссылку на раздел другой страницы?**

Использовать href="index.html#advantages". Браузер открывает index.html и находит в нём элемент с id="advantages".

**6. Почему навигация должна быть единой на всех страницах?**

Одинаковые подписи, адреса и порядок позволяют предсказывать переходы на любой странице. Меняется отметка текущей страницы, а не смысл меню.

**7. Для чего используется тег nav?**

nav обозначает область навигации. Это семантическая подсказка браузеру и вспомогательным технологиям; само по себе оформление меню не создаёт.

**8. Почему на странице должен быть только один тег main?**

В обычной странице должен быть один видимый main с главным уникальным содержимым. Это позволяет однозначно выделить основную область; скрытые представления сложных интерфейсов — отдельный случай.

**9. Для чего нужны хлебные крошки?**

Хлебные крошки показывают положение в структуре сайта и путь к родительским разделам, например «Главная / Каталог / Клавиатура».

**10. Почему текущую страницу в хлебных крошках лучше делать через span, а не через ссылку?**

Текущая страница уже открыта, и ссылка на себя обычно не добавляет действия. span обозначает текст; при необходимости aria-current="page" дополнительно указывает текущую позицию. Это рекомендация, а не запрет ссылок.

**11. Для чего нужен уникальный title?**

title задаёт название документа во вкладке, истории и закладках; уникальное значение позволяет различить страницы. Это не видимый заголовок h1.

**12. Для чего нужен meta name="description"?**

meta description кратко описывает содержимое. Поисковик может использовать его в сниппете, но не обязан. Он не меняет текст страницы и не гарантирует позицию в поиске.

**13. Что делает свойство scroll-behavior: smooth?**

Задаёт плавную прокрутку при навигационных переходах и некоторых программных прокрутках. Обычное вращение колеса мыши это свойство не превращает в другую анимацию.

**14. Что делает псевдокласс :target?**

:target выбирает элемент, id которого совпадает с фрагментом URL. Например, после #popular можно выделить соответствующий раздел рамкой.

**15. Почему дополнительные SEO-элементы лучше выполнять после базовой структуры страниц?**

Сначала должны существовать корректные страницы, ссылки и содержимое. Карта сайта и Open Graph дополняют эту основу; они не исправляют сломанное меню или отсутствующую форму.

### Практическая №6

**1. Для чего используется Flexbox?**

Flexbox — система раскладки вдоль основной оси. В проекте удобна для меню, пары кнопок и вертикального содержимого карточки.

**2. Для чего используется CSS Grid?**

Grid управляет сеткой строк и столбцов. В проекте используется для карточек и двух областей каталога.

**3. Чем Flexbox отличается от Grid?**

Flexbox прежде всего распределяет элементы вдоль одной оси; Grid задаёт отношения сразу по двум измерениям. Это ориентир выбора, а не ограничение количества рядов у Flexbox.

**4. В каких случаях лучше использовать Flexbox?**

Для меню, горизонтальной группы действий, выравнивания содержимого карточки и распределения свободного места вдоль одной оси.

**5. В каких случаях лучше использовать Grid?**

Для согласованных строк и колонок: каталога карточек, раскладки «фильтры + товары», сложной области страницы.

**6. Что делает display: flex?**

Делает контейнер flex-контейнером; его непосредственные элементы участвуют в Flexbox-раскладке.

**7. Что делает justify-content?**

Распределяет свободное пространство и выравнивает содержимое вдоль основной оси Flexbox. В Grid свойство выравнивает сетку вдоль строчной оси.

**8. Что делает align-items?**

Во Flexbox задаёт выравнивание элементов по поперечной оси. При flex-direction: column это уже не обязательно вертикальное выравнивание.

**9. Для чего используется gap?**

Задаёт промежутки между элементами или треками. Внешний отступ контейнера этим не создаётся.

**10. Что делает flex-wrap?**

Разрешает или запрещает перенос flex-элементов на дополнительные строки. По умолчанию nowrap: перенос не включён.

**11. Что делает display: grid?**

Делает контейнер grid-контейнером. Непосредственные элементы становятся grid-элементами.

**12. Что задаёт grid-template-columns?**

Определяет столбцы сетки и их размеры. Например, 240px minmax(0, 1fr) — фиксированная колонка и оставшееся пространство.

**13. Что означает 1fr?**

Одна доля распределяемого свободного пространства Grid. 1fr 2fr делит это пространство примерно в отношении 1:2 с учётом правил расчёта треков.

**14. Для чего используется repeat()?**

repeat() сокращает повторяющееся описание треков: repeat(3, 1fr) вместо 1fr 1fr 1fr.

**15. Для чего используется minmax()?**

minmax(min, max) задаёт нижнюю и верхнюю границу трека. minmax(0, 1fr) позволяет равномерным колонкам сжиматься без автоматического минимума по содержимому.

**16. Что такое grid-template-areas?**

grid-template-areas задаёт именованную схему областей строками. Одна строка "filters products" описывает две области рядом.

**17. Для чего используется grid-area?**

grid-area назначает элементу именованную область либо задаёт его границы в сетке. Например, .catalog-filter { grid-area: filters; }.

**18. Почему в проекте можно одновременно использовать Flexbox и Grid?**

Они решают задачи разных уровней: Grid раскладывает карточки, Flexbox выравнивает цену и кнопки внутри каждой карточки.

**19. Почему адаптивная вёрстка вынесена в отдельную практическую работу?**

Чтобы сначала освоить распределение места и оси, затем поведение на разных размерах экрана. Уже имеющуюся адаптивность удалять не нужно.

**20. Почему БЭМ-рефакторинг выполняется отдельно?**

Рефакторинг меняет организацию и имена, поэтому его удобно проверять отдельно от изменения расположения. Так легче установить причину регрессии.

### Практическая №7

**1. Что означает аббревиатура БЭМ?**

Блок, элемент, модификатор. В учебной работе используется схема block__element и block--modifier.

**2. Что такое блок?**

Самостоятельный интерфейсный компонент, например product-card. Он должен иметь понятное назначение и быть переносимым в другое место.

**3. Что такое элемент?**

Смысловая часть блока, например product-card__title. Её имя показывает принадлежность к компоненту.

**4. Что такое модификатор?**

Вариант или состояние блока/элемента, например button--secondary или site-nav__link--active. Базовый класс при этом сохраняют.

**5. Как записывается элемент в БЭМ?**

Через двойное подчёркивание: order-form__label. Элементы не образуют цепочки вроде block__element__child.

**6. Как записывается модификатор в БЭМ?**

В выбранном стиле — через двойной дефис: button--secondary либо product-card__badge--sale. У БЭМ есть и другие соглашения; в одном проекте выбирают последовательный вариант.

**7. Почему блок должен быть самостоятельным?**

Самостоятельность облегчает перенос и повторное использование. Карточка не должна требовать, чтобы её обязательно поместили именно в один конкретный sidebar.

**8. Почему элемент не должен существовать отдельно от блока?**

Его роль определяется родительским блоком на смысловом уровне. Это не требование находиться непосредственным ребёнком в DOM: вложенность разметки может быть глубже.

**9. Почему классы red, big, left считаются плохими именами?**

Они описывают текущий вид вместо назначения: после изменения дизайна имя red станет ложным. В БЭМ-проекте осмысленнее button--danger. В utility-фреймворках классы вида text-red имеют другой, намеренный принцип.

**10. Почему лучше избегать стилизации через id?**

id имеет высокую специфичность и уникален в документе; классы лучше подходят повторяемым компонентам. id сохраняют для ссылок, подписей и JS.

**11. Почему inline-стили усложняют поддержку проекта?**

Оформление распределяется по HTML, его сложнее переиспользовать и централизованно менять; обычные классовые правила его не переопределяют напрямую.

**12. Как БЭМ помогает уменьшить вложенность CSS-селекторов?**

Селектор .order-form__input называет нужный элемент без цепочки .page .form div input. Поэтому изменение вложенных контейнеров меньше влияет на стили.

**13. Почему карточку товара удобно оформить как блок product-card?**

Карточка содержит связанные заголовок, описание, цену и действия и повторяется в каталоге и на главной. Общий блок сохраняет единое поведение оформления.

**14. Почему кнопка может быть самостоятельным блоком button?**

Одинаковый внешний вид кнопки нужен в карточке, форме и окне. button задаёт общие стили, а product-card__button может выступать отдельным смешанным классом для роли в карточке.

**15. Почему форму и модальное окно лучше разделить на блоки order-form и order-dialog?**

Форма может существовать и в окне, и на отдельной странице. order-dialog отвечает за оболочку окна, order-form — за поля и отправку.

**16. Что нужно проверить в JavaScript после переименования классов?**

Все querySelector/querySelectorAll, делегирование и переключение классов. После изменения селектора в HTML обновляют соответствующий JS и проверяют сценарии; id нельзя переименовывать независимо от getElementById.

**17. Как понять, что рефакторинг выполнен успешно?**

Имена и селекторы согласованы, внешний вид и пользовательские сценарии сохранены, нет новых ошибок консоли и лишних дубликатов. Наличие подчёркиваний само по себе этого не доказывает.

### Практическая №8

**1. Почему каждая контрольная работа выполняется в отдельном репозитории?**

Чтобы отделить исходники, историю, требования и результат каждой КР. №2 использует фреймворк, а №1 остаётся самостоятельной HTML/CSS-реализацией.

**2. Чем многостраничный сайт отличается от одностраничного?**

Многостраничный вариант содержит несколько HTML-документов с переходами. Одностраничный может быть одним документом с разделами; SPA — отдельная архитектура с программной сменой представлений.

**3. Какие страницы должны быть в КР №1?**

Главная index.html, каталог catalog.html, товар product.html, заявка order.html и контакты contacts.html.

**4. Для чего нужна единая навигация?**

Чтобы основные переходы были доступны и предсказуемы на каждой странице, а текущее положение — понятно.

**5. Для чего используются якорные ссылки?**

Для перехода к конкретному элементу по id текущего или другого документа: #popular либо index.html#popular.

**6. Почему важно использовать семантические теги?**

Они отражают назначение областей, облегчают чтение кода и навигацию вспомогательными технологиями. Семантика не заменяет проверку доступности.

**7. Почему на странице должен быть только один тег main?**

Один видимый main однозначно обозначает главное содержимое обычной страницы; шапка, общее меню и подвал не должны превращаться во второй main.

**8. Для чего используется тег article?**

Для самостоятельного материала, например карточки товара. Не каждый контейнер автоматически является article.

**9. Для чего нужна таблица в HTML/CSS-проекте?**

Для связанных табличных данных: характеристика — значение. Таблица не служит заменой Flex/Grid для раскладки страницы.

**10. Для чего нужна форма заявки?**

Для структурированного ввода данных заявки. Поля получают подписи, имена и ограничения, но реальную передачу должен обеспечивать серверный сценарий.

**11. Чем CSS-модалка отличается от <dialog>?**

CSS-модалка обычно управляет видимостью стилями, например через :target. dialog — нативный HTML-элемент; showModal() даёт модальный верхний слой, фон и базовое управление фокусом. Корректность подписей и сценария всё равно проверяют.

**12. Для чего нужны CSS-переменные?**

Для единого хранения повторяемых значений: цвета, радиусы, интервалы. var(--color-primary) подставляет значение пользовательского свойства.

**13. Почему важно оформлять состояния :hover и :focus-visible?**

hover показывает состояние под указателем, focus-visible помогает увидеть положение клавиатурного фокуса. Действие должно быть понятно и без наведения мыши.

**14. Для чего используется Flexbox?**

Для раскладки и выравнивания вдоль основной оси: меню, кнопок и содержимого карточки.

**15. Для чего используется CSS Grid?**

Для согласованной сетки строк и столбцов: карточек и областей каталога.

**16. Что такое БЭМ?**

Подход к организации компонентов и их именованию как блоков, элементов и модификаторов.

**17. Чем блок отличается от элемента?**

Блок может использоваться самостоятельно, элемент описывает часть конкретного блока: product-card и product-card__title.

**18. Чем элемент отличается от модификатора?**

Элемент — часть компонента, модификатор — вариант или состояние этой части либо всего блока.

**19. Почему не рекомендуется стилизовать элементы через id?**

Классы легче повторно использовать и переопределять без повышенной специфичности. id оставляют для адресации элементов и связей.

**20. Что должно быть указано в README.md?**

Название, тема КР, назначение, технологии, структура, запуск, ограничения, ссылка на публикацию, сведения об авторе и описание доработок.

**21. Какие элементы проекта были доработаны самостоятельно?**

Называй только то, что сам действительно изменил и понимаешь. В текущем коде есть SVG-иллюстрации, автоматический выбор товара из URL и дополнительные страницы; сам факт присутствия кода не доказывает самостоятельность авторства.

**22. Почему выбранная самостоятельная доработка улучшает проект?**

Объясни эффект конкретно: например, выбор товара из URL избавляет от повторного выбора в форме. Дополнительно покажи код и проверку сценария; смена цвета без осмысленной задачи сама по себе мало что доказывает.
